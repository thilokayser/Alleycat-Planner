# Implementation Notes

Deep "why we built it this way" detail for Alleycat Dispatch's features — split out of `CLAUDE.md` (2026-08-19) to keep that file under ~5k tokens for fast per-session loading. `CLAUDE.md` has the map (module layout, storage seams, code conventions, known issues); this file has the archaeology behind individual features, for whenever that level of detail is actually needed.

Cross-reference: [`alleycat-dispatch-roadmap-14-23.md`](alleycat-dispatch-roadmap-14-23.md) is the roadmap/changelog with per-package status and dates; this file goes deeper on *how* specific pieces work internally, without the package/date framing.

## Core app structure

- **`CHECKPOINT_TYPES`** (`checkpoint.js`, a mutable `let`) is the single source of truth for checkpoint kinds. User-defined custom types get merged in at load time from `checkpointTypes:custom` in storage and must stay after the built-in types (`BUILTIN_CHECKPOINT_TYPE_KEYS`) when persisted.
- **`THEMES`** and **`ICON_PACKS`** (`ui-headquarter.js`) drive the Settings page; themes are pure CSS variables swapped via `data-theme` on `<html>` (see `src/styles/themes.css`), icon packs lazy-load their CDN (Font Awesome / Material Symbols) on selection.
- **Race status machine** (`race-state.js`): `evt.status` moves `planning → ready → running → completed` (backward always allowed, with a confirm). Forward transitions are validated (`markReady` blocks without ≥1 checkpoint + `expectedRiders` set; `completeRace` warns about riders without a finish time, excluding those marked DNF/DNS); only reachable via `onStatusSelectChange()` (topbar dropdown) or the blocking start-time dialog (`checkStartDialog()`, polled every second from `init()`, renders into `#start-dialog-root` — independent of `render()`/the active view since it must persist across navigation). `isCpLocked(evt)` gates checkpoint structure edits in `checkpoint.js`'s `renderSidebar()` once `status` is `running`/`completed` (with a `cpLockOverride` escape hatch during `running`) — this is the only read-only enforcement in place; other views do not yet respect race status.
- **Rider race status** (`rider.raceStatus`, `''|'dnf'|'dns'|'eliminated'`, set via `setRiderRaceStatus()` in `checkin.js`): independent of `finishTime` — `riderStatusBadgeHtml()` checks it before falling back to curfew logic. Confirming a rider at the finish (`confirmRiderAtFinish()`) always clears it.
- **Category groups** (`category.js`): `evt.categoryGroups = [{id, name, options[], sortOrder}]`, orthogonal to and independent of the Teams system. `rider.categories = {[groupId]: selectedOption}`. Option values are raw user text (from presets or custom input) and never go through `t()` — same rule as checkpoint/team names. Renaming or deleting an option cascades into every rider's assignment; deleting a group clears the corresponding key on every rider.
- **Team scoring mode** (`evt.teamScoringMode`, `'bestTime'|'allMustFinish'`, set in `rider.js`'s Teams section): `computeTeamStats()` in `team.js` computes `bestTime`/`worstTime`/`allFinished` per team and sorts accordingly — `bestTime` ranks by the fastest member's finish time, `allMustFinish` requires every member to have finished and ranks by the slowest member's time (teams with an unfinished member sort last).
- **Checkpoint order mode** (`evt.checkpointOrderMode`, `'frei'|'fest'`, toggle in `checkpoint.js`'s `renderSidebar()`): purely advisory in `'frei'`. In `'fest'`, `checkin.js`'s `checkOrderBeforeComplete()` gates `onCheckinToggleCheckpoint`/`onCheckinSetScore` — completing a checkpoint out of `order` sequence prompts a confirm; accepting appends `{checkpointId, at}` to `rider.checkpointOrderOverrides` as an audit log. Distance (`computeRouteLegs()` in `utils.js`, plain Haversine on CP coordinates, no API call) is only shown in `'fest'` mode, per-leg between consecutive `cp-row`s plus a total — intentionally omitted in `'frei'` mode since sequence-less checkpoints have no meaningful "route length".
- **Overview tab / dashboard widgets** (`dashboard.js`): a per-event "Übersicht" tab (`state.view === 'overview'`, `openOverview()`/`renderOverview()`), separate from the HQ home view (`state.view === 'dashboard'`, event list). `DASHBOARD_WIDGET_KEYS` is the widget catalog (`statusTiles`/`cpLoad`/`recentActivity`/`categoryDistribution`/`miniLeaderboard`/`countdown`/`todos`); each has a `compute*`/`render*Widget` pair. Visibility and order are stored per-event on `evt.dashboardWidgetOrder`/`evt.dashboardWidgetVisibility` (defaults: statusTiles/cpLoad/countdown visible, rest hidden) and edited via the in-page settings panel (`toggleOverviewSettings()`, checkbox + up/down reorder — no drag-and-drop). `computeDashboardTodos()` surfaces only structural completeness gaps (missing checkpoints/positions/start time/capacity/unassigned category groups/unprinted bibs+spokecards/no manifest yet/checkpoints without personnel) — no time-threshold warnings. The countdown widget ticks live via `startOverviewTick()`/`updateOverviewCountdown()` (same self-stopping `setInterval` pattern as `checkin.js`'s live countdown, keyed on `state.view !== 'overview'`), patching `#overview-countdown-value` directly rather than a full re-render.
- **Checkpoint-load display scope**: the "how many riders have checked in at this checkpoint" count is intentionally shown only in the Übersicht's "Checkpoint-Auslastung" widget (`computeCheckpointLoad()`/`renderCpLoadWidget()`), not duplicated onto the map/editor view's checkpoint sidebar rows — the map view is for structural editing (position/type/personnel), not live monitoring.
- **Per-checkpoint lock** (`cp.locked`, toggled via `toggleCpLocked()` in `checkpoint.js`): independent of and orthogonal to the race-status CP lock (`isCpLocked(evt)`) — protects a single checkpoint's position/type/clue/staff from edits (and blocks `moveCp`/`duplicateCheckpoint`/`confirmDeleteCp`) regardless of race status, for e.g. a scouted-and-confirmed position. The sidebar row computes `itemLocked = isCpLocked(evt) || cp.locked` and swaps in the same read-only `cp-edit-readonly` block used for the race-status lock when either is true.
- **Checkpoint list enhancements** (`checkpoint.js`): each `cp-row` shows a time-window status badge (`cpTimeWindowStatus()` → `upcoming`/`open`/`closed`, computed at render time, not ticking), a personnel count badge, and duplicate/lock quick-action icons. `state.cpListGroupBy` (`'order'|'type'`) toggles between the normal sequence list and CHECKPOINT_TYPES-grouped sections (`renderCpListRows()`) — drag/move controls are hidden in the grouped view since reordering across type groups isn't meaningful.
- **Checkpoint personnel** (`cp.staff = [{id, name, phone, role, shiftNote, notes}]`, CRUD via `addCpStaff()`/`removeCpStaff()`/`onCpStaffFieldChange()`): edited inline in the checkpoint's edit form, phone numbers rendered as `tel:` links. **Never** surfaced in `exportManifestPDF`/`buildRiderSheetDoc`/`buildSpokeCardsDoc` (rider-facing) — the only export that reads `cp.staff` is the separate, organizer-only `buildStaffBriefingDoc()`/`exportStaffBriefingPDF()` in `export-pdf.js`.
- **Beamer view** (`beamer.js`): a fullscreen, forced-dark route at `#/beamer/<event-id>`, completely outside the normal `state`/`render()` SPA machinery — `init()` checks `isBeamerRoute()` first and branches to `initBeamer()`, which hides `#app` and shows the sibling `#beamer-root` container. Own lightweight `beamerState` object (`{eventId, evt, phase, audioBlocked}`, phase `'countdown'|'go'|'live'`) is kept separate from the HQ's global `state`. Sync: `getBeamerChannel()` wraps a `BroadcastChannel('alleycat-beamer')` (`null` if unsupported); `broadcastRaceStart()` fires on `startRace()` for instant GO-trigger reaction, `broadcastEventUpdated()` fires after every successful save so any open beamer tab reloads — a 7s `setInterval` poll (`loadBeamerEvent()`) is the fallback if a broadcast was missed. Live phase re-derives rank/underway/DNF-DNS groupings from scratch on every update via `sortBeamerRiders()` (no incremental diffing) and ticks only the race-clock text node every second, not the whole table, so the beamer screen doesn't flicker for an audience. **Never mutate `location.hash` from within `test-suite.js`** — `init()`'s own `hashchange`→`location.reload()` listener would abort the running suite.
- **Sound-hook module** (`sound-hook.js`, deliberately generic, not beamer-only): `AlleycatSounds.register(key, dataUrl)`/`.play(key)` (resolves `false`, never throws, for an unregistered key or blocked/failed play)/`.isRegistered(key)`/`.unregister(key)`. `SOUND_EVENTS` is the full catalog. Per-event storage: `evt.soundHooks = {[key]: {name, dataUrl}}` (base64, 2MB cap), wired into the live registry via `registerEventSounds(evt)` on every HQ/beamer event load.
- **Auto-backup** (`data-safety.js`): `state.appSettings.autoBackupEnabled` (device-local, default **off**) gates `runAutoBackupTick()` before its "is a race running" check. `startAutoBackup()` runs one `setInterval` for the app's lifetime. `triggerBackupNow(silent)` calls the `exportBackupBlob()` seam, triggers a real `<a download>` click, sets `evt.lastBackupAt`; first-ever download in a session shows a one-time repeated-download-prompt warning. Whole feature hidden when `hasSharedStorage`.
- **Beforeunload warning + running-hint**: a dedicated `beforeunload` listener calls `e.preventDefault()` when the current event's `status === 'running'`; a `⚠ Tab bitte offen lassen` hint (`.running-hint`) also renders into the topbar whenever running, since browsers only show generic confirmation text.
- **Wake Lock**: `requestWakeLock()`/`releaseWakeLock()` wrap `navigator.wakeLock` (no-op if unsupported). `syncWakeLockForView()` holds the lock only while `state.view === 'checkin'` on a `running` event; the beamer requests it unconditionally once, independent of that sync.
- **Offline map-tile cache** (`offline-tiles.js`): a separate, raw `indexedDB` store (`alleycat-tiles`/`tiles`, keyed `"{z}/{x}/{y}"`) — outside the storage abstraction since it's a per-device cache, not app data. `createOfflineTileLayer()`'s `createTile()` checks cache → falls back to network → falls back to a grey placeholder. `detectRetina` is deliberately off so live tile requests match the cache keys built during download. `tilesForEvent(evt)` covers a checkpoint bbox +500m at zoom 13–17. Staleness (`offlineTileCacheStaleness()`, `>24h` warn, `>3 days` danger) feeds `computeDashboardTodos()`.
- **PDF-Baukasten** (`pdf-blocks.js`): `evt.pdfBlocks = [{id, type, targetDocuments[], enabled, sortOrder, content, config{}, width, pageBreakBefore}]`. `layoutBlocks()` auto-flow-packs blocks into rows by `width` (`full`/`half`/`third`) + `pageBreakBefore`; `appendPdfBlocks(doc, evt, targetDocType)` in `export-pdf.js` gives every **row** (not every block) an unconditional fresh page — the key backward-compat trick, since a legacy full-width-only event's blocks each form their own row anyway, so old events paginate identically to before. Enabled blocks append as extra pages after a document's existing content (manifest + spokecards only, never startnummern/staff-briefing). Unit-agnostic: margins/line-heights are fractions of `doc.internal.pageSize.getWidth()/getHeight()`, only `setFontSize()` stays fixed-pt.
- **Spielmodi-Engine** (`rules-engine.js` + `game-modes.js`): `evaluateRules(evt, triggerType, context)` is the single generic dispatch every trigger point (check-in, finish, a 10s `on_tick`, manual organizer actions) goes through. It looks up each enabled mode's static rule list in `GAME_MODE_DEFS[mode.type]` and runs matching `{trigger, condition, effect}` entries; an effect can veto the triggering action via `{block, message}`. 7 presets: `time_window`, `first_n` (Bonus-CPs via `cp.mandatory === false`), `prerequisite` (Geheime CPs, event-level reveal state), `zone_active` (Battle Royale, zone-system-backed since Paket 4), `rider_flag` (Wildcard/Joker), `sequence_match` (Kettenreaktion bonus on a perfect fest-order finish), `sudden_death` (elimination via `lastCheckpointTimeForRider()`). "Kopfgeld" is explicitly out of scope. **Numeric config gotcha**: see Known issues in `CLAUDE.md` — never `config.x || default`. Points: `evt.pointsLedger`, keyed by `riderBib` (riders have no separate `id`). Enabling a points-awarding mode flips `evt.scoringMode` to `'points'`, `leaderboard.js` ranks accordingly.
- **Live-Beamer für Spielmodi** (`beamer-modes.js` + `live-sync.js`): `getBeamerLayout(evt)` is the single switchboard every widget is gated behind, so a mode-less event renders the plain beamer unchanged. `pushEventLog()` appends to `evt.ruleRuntimeState.eventLog` (capped 30), gated on any mode being enabled. A second `BroadcastChannel('alleycat-live')`, separate from the beamer's own channel, only ever affects *latency* — storage stays the source of truth, a missed broadcast is caught by the existing 7s poll.
- **QoL: Bulk-Import, Error Boundary, Undo-Log**: **Bulk-Import** (`bulk-import.js`) is a 3-step panel (upload → column-mapping → review); `parseCsvText()` is hand-rolled with `detectCsvDelimiter()` auto-picking `,`/`;`; `runBulkImportValidation()` collects missing/duplicate Startnummer errors and excludes those rows rather than silently skipping. **Undo-Log**: `evt.actionLog` (persisted, last 5) populated by `logUndoableAction(evt, label, undoFn)` — deliberately not a generic state-diff system, each call site supplies its own reversal closure. The closures themselves are runtime-only (`state.actionUndoHandlers`, cleared on `openEditor()`) — log entries survive reload as an audit trail, but "undo" only works within the session. **Error Boundary**: module-scope `window.addEventListener('error'/'unhandledrejection')` listeners (registered at load time, not inside `init()`) call `showErrorBoundary(err)`, a full-screen non-dismissable overlay — "Daten sind sicher" is true by construction since every mutation already goes through `debouncedSave()` before any UI code runs.

## UI-Politur packages (Paket 1–2, Phase 19+16)

- **Paket 1 — UI-Efficiency wins** (`command-palette.js`, `map.js` sidebar-collapse, global keyboard shortcuts, Outdoor high-contrast theme, hover-sync, checkpoint bulk-actions, in-page PDF preview): pulled forward ahead of "MVP before UI polish" since it's the fastest path to real user feedback. `initGlobalShortcuts()` — digits `1`–`6` navigate, Cmd/Ctrl+K toggles the palette, Esc runs a priority chain (`handleGlobalEscape()`). Command Palette (`commandPaletteFuzzyScore()`) is a hand-rolled substring-first/subsequence-fallback matcher, no library. Outdoor theme is a light-theme variant pushed to max contrast with a dedicated `:root[data-theme="outdoor"]` CSS block enlarging touch targets (no `rem` usage in this codebase, so no root-font-size shortcut). **Gotcha, root-caused during this phase**: `map.invalidateSize()` must be called **synchronously**, never via `setTimeout` — a deferred call can fire after navigating away from the editor, caching a 0×0 size that Leaflet then reuses for every future `flyTo()`/pixel calc until re-invalidated while actually visible. Worth remembering for any future Leaflet-sizing code.
- **Paket 2 — Feature-Registry & Settings-Hub** (`feature-registry.js`, `empty-states.js`, `social-share.js`): `FEATURE_REGISTRY` array (`{id, scope, icon, name(), description(), defaultEnabled, configScreen}`), `scope:'device'` persists to `state.appSettings.featureToggles`, `scope:'event'` to `evt.featureFlags` — a pure UI-visibility flag, never touches the underlying data model (turning `categories` off hides the UI, `evt.categoryGroups` is untouched). `jumpToFeatureConfig(screen)` looks up `{open, anchor}` per `configScreen` id and navigates + scrolls. `emptyStateHtml({icon, title, description, primaryAction, secondaryAction, compact})` generalizes the pre-existing ad hoc `.empty-state` pattern. Social-share cards are a manual-trigger-only Canvas renderer using the active theme's live CSS variables, not a hardcoded palette.

## `php-backend/`

Separate deployment target (PHP + MySQL, no framework), consumed only by the server variant. `install.php` is a one-time web installer (creates `kv`/`db_meta` tables, generates an API key, writes `config.php`, then self-deletes). `api.php` is the REST endpoint (`GET`/`POST`/`DELETE` via `?key=...`, `X-Api-Key` header) mirroring the `storageGet`/`storageSet`/`storageDelete` contract. `config.php` holds DB credentials + the API key **hash** and is gitignored.

- **Backend-Härtung** (`preflight.php` + `migrations.php` + `bootstrap.php` + `backup.php` + `migrate.php`): the app can't be pre-tested against every shared host, so it detects and communicates environment limits at install time. `runPreflightChecks()` checks PHP version/extensions/writability/limits with no DB needed; `runDatabasePreflightChecks()` runs once credentials exist, feature-detecting `utf8mb4` support via a real `SET NAMES` attempt rather than a version-string comparison. Each check is `{id, label, level: 'ok'|'warn'|'error', detail}`; `install.php` blocks on any `error` unless an explicit, server-revalidated override checkbox is checked. `migrations.php` tracks a single integer `schema_version` in `db_meta`; migrations are idempotent (`CREATE TABLE IF NOT EXISTS`) rather than transactional, since MySQL/MariaDB DDL commits implicitly anyway. `bootstrap.php` centralizes config loading, key verification (supports both the new `password_verify()` hash and a legacy plain `hash_equals()` for already-installed backends), DB connection, and production error hardening (`display_errors` off, generic JSON error responses, real detail only in `error_log()`) — deliberately **not** applied to `install.php` itself, which is one-time/self-deleted and needs to show real connection-failure reasons to be usable. `backup.php`/`migrate.php` are new maintenance endpoints for hosts without CLI/cron access.
- **Verified empirically** against a real local MariaDB instance (see `php-backend/COMPATIBILITY.md`): 20 concurrent writes to the *same* key never corrupt the row (MySQL's `INSERT … ON DUPLICATE KEY UPDATE` is atomic), but the "one key = one whole event JSON blob" model still means the *last* writer's full blob wins over any concurrent one — a real, documented, unfixed limitation (see Known issues in `CLAUDE.md`). A 100-concurrent-writes-to-100-independent-keys load test completed in under 5s with zero cross-contamination, using `PHP_CLI_SERVER_WORKERS=8` (needed because PHP's built-in dev server is otherwise single-threaded and would just serialize "concurrent" requests). **Still not verified**: a real shared-hosting install (see Known issues in `CLAUDE.md`).
